Four agents.
One window.

Each one in its own git worktree. The one that has stopped and is waiting on you says so, on its own border, without being asked.

macOS, paste into Terminal

brew install tmux fzf fd micro bat

Windows, inside WSL2

sudo apt install -y tmux zsh git fzf fd-find micro bat && mkdir -p ~/.local/bin && ln -sf "$(which fdfind)" ~/.local/bin/fd

then, on either

git clone https://github.com/ZyxWorks/agent-office.git ~/agent-office && ~/agent-office/install.sh

Then office on. The installer adds one line to your .zshrc, one to your .tmux.conf and a symlink, and no keyboard map in any terminal: every key is Shift+arrow or the Ctrl+Space prefix, which every terminal already sends. Closing the window kills nothing.

MIT licensed, and all of it is on GitHub before you run any of it: the installer is one shell script you can read first, and so is everything it installs — about two thousand lines of zsh and a tmux config, no daemon, nothing compiled.

What was in the way

Running three or four coding agents at once is normal now. The tooling for it was not: a heap of terminal windows, a layout you rebuilt every morning, and no idea which one was stuck. Every window looked equally busy, so finding the one waiting on you meant reading all four — then doing it again five minutes later. That last part is why this exists. The window is the easy half.

Four agents you can keep track of is a different tool from four agents in four windows.

Four is the cap because a fifth session in a fifty-row window gets about nine rows, which is a slit and not a desk. Twenty seconds is the default and it is one variable.

How it knows which one stopped

It watches the pane, not the agent. There is no marker to grep for and no hook to install, because the left column is pointed at whatever CLI you use — so the only thing it can rely on is that an agent that is working redraws: a spinner, an elapsed timer, output arriving. One that has stopped does not.

Two looks, because either alone is wrong: a hint line under the input box rotates every eight seconds, so "nothing moved" cannot mean idle, and a thinking agent moves exactly one line, so "one line moved" cannot mean idle either. Measure your own.

What it does not do

  • No daemon. Nothing runs between sessions, and office off takes the tmux server and every process its panes started, detached ones included.
  • No config file. Every setting is an OFFICE_* environment variable, and the defaults are the product.
  • No plugin system, and no package manager. Two files and three small helpers is the whole surface.
  • No hiding what it costs. Measured with its own office doctor: an agent pane is about 500 MB, while the office's own shell pane is 9 MB and its file list 16 MB. Four agents is a RAM decision, so there is a command that shows you the bill.
  • No context number on a non-Claude desk. That readout comes from Claude Code's own session files, so a codex or aider desk simply has none rather than a guess.
  • No native Windows. tmux does not run there, so this lives in WSL2 and says so instead of half working.
  • No telemetry, and one network call you can switch off. office on runs git fetch against this repo's remote to tell you when you are behind, and never pulls on its own. OFFICE_UPDATE_CHECK=0 removes even that. Nothing else here opens a socket.

Five probes drive a real tmux server to check all of this, attaching real clients on a pty and typing raw bytes at them, and CI runs every one of them on macOS and Ubuntu — tmux 3.7b and 3.4 — on every push. The source is public, and so is every claim on this page.
